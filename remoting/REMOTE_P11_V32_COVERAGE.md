Coverage is checked, not just described: `scripts/check_coverage_ledger.py` fails the gate if any compliance category has no ledger row, any `case_ids` entry names a test function that doesn't exist, or any RPC on the `Pkcs11V32` gRPC service has zero mention anywhere in the ledger.

**99 of 104** `pkcs11f.h` functions are live RPCs. The remaining 5 (`C_Initialize`, `C_Finalize`, `C_GetFunctionList`, `C_GetInterface`, `C_GetInterfaceList`) are deliberately not mirrored: All five are N/A-local, not gaps: C_Initialize/C_Finalize are server-process bootstrap lifecycle with no per-request network analogue (see the 'Init' row below); C_GetFunctionList/C_GetInterface/C_GetInterfaceList return function-pointer tables, which are meaningless over a wire — a remote client cannot call through a returned pointer. None of the five map to a named category in cpp_compliance_report.json, so they have no row in `rows` below; documented here instead so the ratchet's silence about them is a deliberate, checked design choice rather than an oversight.
