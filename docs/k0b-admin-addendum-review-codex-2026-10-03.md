1. **A-01 — high — §3.4, Admin receipt.** `AdminTbsReceipt` says `signerChain` is carried inside the TBS, but the ASN.1 definition omits that field. A verifier therefore cannot determine the signing certificate from the receipt, and implementations may invent incompatible out-of-band rules. It also leaves no normative equality check between `deviceID` and the receipt-signing chain. **Fix:** add `receiptSignerChain SEQUENCE SIZE(2) OF Certificate` to `AdminTbsReceipt`; require the receipt-signing leaf and device issuer profiles, chain/CRL validation, and equality between `deviceID` and the chain-derived device ID.

2. **A-02 — high — §6, KMIP transport binding.** The binding does not serialize all parameters of the frozen v1 calls. `ImportReplicationPackage` needs a package and a `CK_ATTRIBUTE[]` template; `CloneKey` additionally needs source and destination sessions; both return a handle. `KeyCall` covers only the source-key handle and request. Consequently, two implementations cannot agree on import templates, destination selection, or output-handle representation. A naïve bridge could silently omit restrictions or expose a process-local handle. **Fix:** define a strict DER input and output envelope for every `(interface, function)` pair, including canonical attribute encoding and bounds. Return `CKA_UNIQUE_ID`, not a handle. Prefer making v1 `CloneKey` unsupported over KMIP because the network ceremony already uses create/import and CloneKey is explicitly same-module.

3. **A-03 — high — §3.2 steps 7–8 and §3.3.** The claimed single atomic commit cannot be obtained by wrapping the current engine functions “unchanged.” `enroll_crl`, `enroll_policy`, `rotate_recovery_key`, and `issue_device_crl_with` each commit and audit internally. A crash after that inner commit but before nonce consumption, sequence advancement, receipt storage, and the wrapper audit leaves an administrative change committed with a reusable request. **Fix:** refactor each operation into validation/staging plus one common AdminExecute commit. No wrapped function may write state or audit independently. Add crash tests immediately before and after every staged object/update and the final transaction.

4. **A-04 — high — §1.1 and §6.2–§6.4, KMIP identity mapping.** “Role bound to the mTLS client certificate” is not defined precisely: no trust anchor, EKU/SAN/OID, certificate profile, role-conflict rule, or mapping algorithm is specified. Current KMIP authentication can replace the transport identity with a header credential or ticket, and current mTLS identity is only the certificate subject CN. Thus a non-admin TLS connection can acquire an admin application identity through header authentication, contrary to the requirement that all controls include the admin mTLS role. **Fix:** preserve transport identity separately from KMIP header identity; authorize these interfaces solely from immutable connection metadata. Define dedicated certificate EKUs or separate client CAs, exact identity-to-role mapping, rejection of dual/ambiguous roles, and prohibit header credentials or tickets from upgrading the transport role.

5. **A-05 — high — §6.3 and §1.1, application-context ownership.** The proposal requires a session in “that connection’s own application context” but does not define how an unforgeable connection context is created, associated with the KMIP handler, destroyed, or prevented from reusing another connection’s session. The present handler/session resolver is identity-oriented, not connection-context-oriented. A faulty implementation could share an SO session across connections or retain it after disconnect. **Fix:** specify a connection-scoped context identifier created after successful mTLS, with sessions created and logged in only inside that context and closed on disconnect/error. The handler must never accept session handles from the wire. Gate advertisement on cross-connection handle/session isolation tests.

6. **A-06 — medium — §6 table, §9.1 allocation.** The document assigns vendor functions ordinals starting at zero, while the existing KMIP handler documents `PKCS#11 Function` as the KMIP-defined one-based offset in a function list. This creates an immediate dispatch disagreement and makes function zero potentially invalid at the KMIP layer. **Fix:** either use one-based KMIP function values while retaining zero-based local registry indices, or normatively define and obtain an extension allocation permitting the alternate convention. Publish explicit wire vectors for every function.

7. **A-07 — medium — §3.2 steps 3–6 and final paragraph.** The verification order rejects an exact committed retry before reaching receipt recovery: its sequence is no longer greater than the counter and its nonce is consumed. Replacement or revocation of the admin certificate may similarly prevent recovery of an already committed receipt. **Fix:** after transport/SO checks and strict parsing, look up a committed entry by the complete request hash and byte-equal request before nonce/sequence freshness checks. Specify whether recovery remains available after admin-key revocation or replacement; because it performs no mutation, retaining recovery is preferable.

8. **A-08 — medium — §3.1–§3.2, sequence semantics.** Accepting any sequence greater than the stored value permits reordering. If sequence 100 is delivered before signed requests 2–99, those requests become permanently unusable. A request using `2^63−1` permanently exhausts the authority’s sequence space. **Fix:** require `sequence == stored + 1`, reject overflow, and define a board-local recovery/rekey procedure for counter exhaustion or loss. If intentional gaps are required, define a separately signed counter-advance operation.

9. **A-09 — medium — §3.1 and §8, ASN.1 and bounds.** The ASN.1 is not a complete module and does not declare explicit versus implicit tagging. `FunctionPurpose` is undefined. `revoke` and `retiredToRevoke` lack count, element-size, ordering, and uniqueness constraints. The top-level 96 KiB limit does not prevent many small elements, duplicate work, or oversized certificate parsing. Implementations will encode the tagged `CHOICE` differently and apply different revocation semantics. **Fix:** publish a complete ASN.1 module with an explicit tagging declaration; define all enum values; bound both lists, each certificate, nesting depth, and resulting CRL entries/DER; require canonical ordering and uniqueness; reject `deviceIssuer` and unknown purposes before cryptography.

10. **A-10 — medium — §3.2, §8 and base §11, durable retry state.** Exact committed retries require a durable request-to-receipt record, but the addendum gives no capacity, retention period, eviction rule, or behavior when the stored receipt is corrupt or absent. An implementation may retain receipts forever and exhaust storage, while another may prune them and violate exact retry. **Fix:** define an admin replay-ledger record, maximum entries/aggregate bytes, retention policy, capacity error, authentication/integrity behavior, and whether tombstones remain after receipt expiry. Never silently evict an entry while its sequence is the only replay barrier.

11. **A-11 — medium — §6 and KMIP batch semantics.** The binding does not address KMIP batch `Undo` or asynchronous execution. The current dispatcher can mark earlier operations `OperationUndone`, but an engine-side administrative commit is not necessarily rolled back; rolling it back would also reset nonce and sequence state. This can produce a response claiming that a revocation or rotation was undone when it remains committed. **Fix:** require these interfaces to execute synchronously and refuse asynchronous indicators and `Undo` batches, or define them as non-undoable and ensure KMIP reports the committed result accurately. Tests should combine a successful admin call with a later failing batch item.

12. **A-12 — medium — §3.2 step 6, §4 and §8, nonce issuance.** The nonce requirements omit minimum entropy, collision handling, all-zero rejection, and behavior when the single reservation already exists. Because `AdminIssueNonce` itself is not admin-signed, a stolen `replication-admin` transport credential can continually occupy or refresh the sole reservation, denying legitimate administration. Returning `CKR_DEVICE_MEMORY` also exposes reservation occupancy. **Fix:** require a uniformly random nonzero 256-bit nonce from the engine CSPRNG, collision checking, and a precise rule such as idempotently returning the existing nonce to the same connection or refusing replacement until expiry. Rate-limit issuance per transport identity and do not extend an existing expiry through repeated calls.

13. **A-13 — medium — §6.8, key resolution.** “Exactly one object matches `CKA_UNIQUE_ID`” is insufficiently scoped. The server must also constrain the lookup to the selected slot/application context and the expected object class/key role before invoking the function. Otherwise a duplicated/corrupt ID produces inconsistent behavior, and AttestKey may resolve an unintended public, private, or data object. **Fix:** specify lookup predicates per operation: slot/context visibility, expected class, eligible key type, private-object authorization, and exactly one match. Keep the final engine-side source-key/attestation checks even after resolution.

14. **A-14 — medium — §3.3 `issueFunctionCerts`.** “Re-issuance retires the old leaves the way rotation does” is incomplete. It does not define which five objects become active atomically, how old private/public/certificate triples are marked, whether old signing keys remain usable, how accessors select the active generation, or how in-flight packages and stored receipts behave. Multiple implementations can expose different generations or continue signing with retired keys. **Fix:** define a generation identifier and an atomic replacement invariant; exactly one active triple per purpose; retired private keys unavailable for new operations; retained certificates still usable for verification; deterministic accessor selection; and crash tests across the complete five-purpose replacement.

15. **A-15 — low — §3.3 `issueDeviceCrl`, compared with current `issue_device_crl_with`.** `retiredToRevoke` is described as retired certificates, but the current function accepts any parsable certificate whose issuer name equals the device issuer; it does not require a valid signature or an exact match to a retained retired certificate. Implementations following the prose and code will differ. **Fix:** require each entry to byte-match a locally retained retired certificate, validate its issuer/signature/purpose, reject active or foreign certificates, and deduplicate serials.

16. **A-16 — low — §5, audit.** The required audit fields are written as though every call contains `adminKeyID`, `requestHash`, and `sequence`, but ceremony calls—and AdminIssueNonce—do not contain all of them. The native function signatures also carry neither KMIP correlation value nor transport identity, despite step 8 requiring the oplog record in the atomic commit. **Fix:** define a per-operation audit schema with optional/mandatory fields, and attach authenticated connection metadata to the application context before invocation. Define how correlation and identity enter the same durable commit without accepting caller-supplied spoofable values.

17. **A-17 — low — §2.1 and §9.1, version evolution.** The text says adding an admin operation changes the signed enumeration and “the version, never the ABI,” but it does not say whether that means the TBS integer, interface version/name, signature prefix, or all of them. Extending the `CHOICE` beneath `ADMIN_1_0` would silently change the advertised 1.0 protocol. **Fix:** declare the 1.0 operation set immutable. Any added operation must use a new interface version/name, TBS version, signature-domain prefix, and allocation entry.

18. **A-18 — low — §8, KMIP input bounds.** The KMIP input cap is stated, but the requirement that bounds be checked “before allocation” cannot be met unless the TTLV/frame decoder enforces a transport length cap before constructing the `Vec<u8>`. Aggregate batch size and output size are also unspecified. **Fix:** define listener/frame, batch, input-parameter, and output-parameter limits and enforce them while decoding lengths, before allocation or DER parsing.

Sound aspects:

- Admin requests bind the target device, active admin key, nonce, sequence, operation, and complete operation payload under a distinct ML-DSA domain string.
- The separate admin, ceremony, and frozen v1 interface names provide useful interface-level domain separation.
- Admin trust-anchor, device-identity, and admin-authority enrollment remain outside the network interfaces, preventing an admin-key compromise from directly replacing its own trust root.
- Post-DER trust failures are intentionally collapsed to `CKR_ACTION_PROHIBITED`, with detailed reasons confined to protected audit.
- The ceremony calls preserve the base protocol’s engine-issued challenges, destination-generated transaction identifiers, policy binding, and strict-DER rules.
- Using `CKA_UNIQUE_ID` instead of transient handles or non-unique labels is the correct basis for remote key references.
- Requiring the feature gate, explicit educational-profile selection, crypto-plane listener, mTLS, real PKCS#11 login, and signed admin request provides sensible layered protection for the stated educational environment.
- The proposal explicitly recognizes snapshot rollback, lack of secure time, timing leakage, and the educational-only network exception instead of claiming protections the software token cannot provide.
