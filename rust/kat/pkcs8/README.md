# PKCS#8 `PrivateKeyInfo` reference encodings

Generated by **OpenSSL 3.6.3** (the version this project pins), one private
key per supported family:

```
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -outform DER -out raw.der
openssl pkcs8 -topk8 -nocrypt -inform DER -in raw.der -outform DER -out p256.p8.der
```

They exist so `pkcs8_private_key_info`'s output is asserted against a **third
party**, not against the engine's own idea of the format. That distinction is
the whole point: the encoder previously emitted the bare stored scalar as the
`privateKey` OCTET STRING for every key type, which round-trips perfectly
through itself and is unparseable by anything else.

| file | curve / algorithm | bytes | `privateKey` content |
|---|---|---|---|
| `p256.p8.der` | prime256v1 | 138 | RFC 5915 `ECPrivateKey` |
| `p384.p8.der` | secp384r1 | 185 | RFC 5915 `ECPrivateKey` |
| `p521.p8.der` | secp521r1 | 241 | RFC 5915 `ECPrivateKey` |
| `k256.p8.der` | secp256k1 | 135 | RFC 5915 `ECPrivateKey` |
| `ed25519.p8.der` | Ed25519 | 48 | RFC 8410 `CurvePrivateKey` |
| `ed448.p8.der` | Ed448 | 73 | RFC 8410 `CurvePrivateKey` |
| `x25519.p8.der` | X25519 | 48 | RFC 8410 `CurvePrivateKey` |
| `x448.p8.der` | X448 | 72 | RFC 8410 `CurvePrivateKey` |

The EC files carry the optional `[1] publicKey` because OpenSSL emits it and
the C++ engine delegates to OpenSSL; the cross-engine differential harness
compares the wrapped length, so the two engines have to agree on that choice.

These are throwaway keys generated solely to pin an encoding. They protect
nothing and are not used as key material anywhere.
